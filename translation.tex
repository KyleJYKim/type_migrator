% TypeSpec and Elixir type are structurally different while they share semantic similarities

% A function annotation in TypeSpec mainly consists of "@spec", input type, and output type. 
% Starting with "@spec" that announces the existence of an annotation, 
% the following expression is divided into input and output types by "::".
% Where input type has a function's name prepending that it specifies and places in between a pair of parentheses.
% In addition, TypeSpec allows to use type parameters by entailing a "when" clause which taken as a type in the whole clause.

% Elixir type features the semantical similarities described above 
% that are "@spec" is replaced by "\$" sign, and input and output types are only distinquished by "->".

% Notwithstanding the similarities, the main difference comes from TypeSpec's support in multi-clause annotations.
% It 

% It can consist of one or more clauses to express the polymorphic nature of Elixir functions.
% (Does order matter in Dialyzer??? Let's check!!!)

% while that in Elixir Type takes a single clause.
% In the case of TypeSpec's multi-clause, it can be represented with `and` between clauses in Elixir Type within a single clause.
% That is because multi-clauses indicates the existence of the matching function.
